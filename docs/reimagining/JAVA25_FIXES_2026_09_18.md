# Java 25 review implementation — 2026-09-18

This ledger maps all **56 findings** in the [review](JAVA25_REVIEW_2026_09_18.md) to the current implementation. It describes the workspace changes, not a release or deployment. The review baseline is `91b9bd74746d27102a96fa47d4e06e0dd25097ca`.

**52 findings are implemented, three are staged, and one is retained for compatibility.** The remaining work concerns broad quantity-type migration, global metric-registry migration, additional SQLite indexes, and separation of packaged legacy writers from historical import support.

**Implemented** means the concrete, bounded recommendation has code and/or test changes. **Staged** means part is implemented and the remaining boundary is stated. **Retained** identifies an intentional compatibility or architectural choice. These labels do not substitute for the qualification results below.

The original review used three **Astra medium reviewers** for application, backend, and policy, with foundation review and cross-component checking by the parent. Three Astra medium implementation agents also handled the application, policy, and backend fixes. The parent reviewed their patches; additional cross-checks covered lifecycle, transactions, metrics, redaction, and benchmark resets. Those independent reviews supplied the finding IDs and preservation requirements. This implementation ledger keeps that source review distinct from subsequent compilation, tests, and quality checks.

## Deliberately preserved boundaries

The original scheduler entrypoint, SQLite transaction/fail-stop machinery, task/update state machines, scheduling policies, public Thrift/HTTP shapes, and offline import contracts remain. No new scheduler, HA implementation, or preview-language requirement is introduced. The existing LAN cluster remains unchanged; qualification uses a separate owned Docker lab. Guava structures remain where ordering, ranges, cache expiry, or service lifecycle are meaningful.

Dynamic task metric lifetime and overflow behavior are documented in [Monitoring](../operations/monitoring.md). Global static metric migration, legacy-writer packaging separation, broader Amount consumer migration, and additional SQLite task indexes require separate compatibility/workload decisions. Reduced repeated work is an implementation property, not a measured speedup.

## Validation

The clean Java build and `verifyOriginalBehavior` passed: **1,456 scheduler tests and 141 commons tests**, with no failures, errors, or skips. Application coverage is **91.73% instructions / 80.98% branches**, above the unchanged 87% / 79% gates. The executable benchmark-fixture check passed five scheduling/reset cycles and validates host/rack, port, and task-ID cardinality; it reports no performance measurement.

The complete `verifyOriginalQuality -Pq` gate passed, including Checkstyle, PMD, SpotBugs, license checks, analyzer compatibility fixtures, and benchmark fixture checks. The subsequent CLI help correction passed affected checks, six focused CLI tests, and installed-distribution verification. The [validation record](java25-review-20260918/validation.md) and [machine-readable receipt](java25-review-20260918/validation.json) distinguish the full gates, follow-up checks, source/artifact hashes, and resolved failures.

A fresh three-container lab passed smoke, health, logs, three-round recovery, policy, and churn acceptance. Churn completed 260 distinct tasks, exactly 130 on each agent, while preserving two service processes and all daemon identities. Both temporary qualification labs were shut down afterward; the existing LAN lab remains unchanged.

Cluster qualification also found and fixed a Go agent outcome bug: an output-pipe drain timeout after a confirmed successful process exit must not turn that exit into a failed task. The corrected agent durably marks potentially incomplete output, preserves measured dropped-byte counts, and passed uncached agent/helper tests and vet before the final cluster run. A rollback fixture now requires 30 seconds of stable running, preventing delayed failure observations from prematurely satisfying its former one-second window. These additional fixes and the retained failed-run evidence are detailed in the validation record.

Validation includes SQLite rollback, nested write and publication-failure outcomes, terminal-only pruning, audit validation, sequential placement and offer indexing, exact quantity/credential semantics, snapshots and metric retirement, lifecycle cleanup, wire/profile compatibility, historical replay, and cancellation fixtures. The targeted-agent dispatch fixture now notifies the actual task created for the second agent; the previous notification could pass only through a startup race.

Analyzer exceptions are narrow and documented: input-bearing exception causes are intentionally omitted at redaction boundaries, and scheduled test futures retain identity equality even when their delays compare equally. The latter SpotBugs exception names only FakeScheduledExecutor's private ScheduledWork class. Existing coverage thresholds and required analyzer tasks remain enabled.

Kerberos credential ownership is tested with controlled GSS/login collaborators; no external KDC qualification or end-to-end IPv6 certification is claimed. Benchmark fixes are workload corrections, not a measured scheduler speedup. The existing LAN lab is unchanged.
