# Java 25 simplification and abstraction review — 2026-09-18

Aurora can be substantially simpler without replacing the scheduler again. The best next work is to correct a few existing boundary defects, make asynchronous resource ownership explicit, reduce repeated storage/aggregation work, and remove dormant implementations. Targeted Java 25 idioms support that work; converting every class to a record or every loop to a stream would obscure several important contracts.

This review covers **all 667 tracked Java files / 103,729 lines** at `91b9bd74746d27102a96fa47d4e06e0dd25097ca` on `codex/in-place-java25`. Three **Astra medium subagents** reviewed application, backend and policy code; the parent reviewed foundation/lifecycle/metrics/benchmarks and checked the highest-priority cross-component findings. Production, test, benchmark and build-support Java are included. Generated, untracked build output is excluded. This supersedes the older file audit as a description of this baseline; it does not undo changes already made.

**This is a review deliverable. No Java implementation or test files changed, no cluster was restarted, and no code was pushed.** One isolated Java 25 probe reproduced three helper defects; other findings are source-reviewed, not new runtime qualifications. The account usage percentage is not exposed by the available tools, so the requested 20% cutoff could not be measured. Work was limited to one complete pass and focused verification.

## Correctness changes should come first

These seven P1 findings deserve separate, behavior-focused changes before broad cleanup. They are implementation priorities, not external security severity ratings.

| Finding | Concrete problem | Proposed change |
| --- | --- | --- |
| APP-001 | Explicitly empty prune statuses bypass terminal-only filtering; the store interprets empty as unrestricted. | Copy/normalize the query and enforce terminal-only deletion, including empty and mixed status sets. |
| APP-002 | Overlong update audit messages are rejected inside SQLite writes, reaching the scheduler's fail-stop handler. | Validate audit input before entering the write and return the intended invalid-request response. Preserve fail-stop for actual write failures. |
| POL-001 | A batch chooses all placements before updating the job's attribute aggregate, allowing several tasks to consume the same remaining rack allowance. | Choose and assign sequentially against the updated aggregate, keeping reservations, offer-use guards and launch failure behavior. |
| POL-002 | CPU-only/resource-only offer comparisons can return equality for distinct offers, so the sorted set loses offers while ID indexes retain them. | Add a stable offer-ID tiebreaker to the configured ordering. |
| FND-002 | BatchWorker completes futures before the enclosing transaction commits; a later item can roll back an earlier reported success. | Stage outcomes/retries until the outer commit, and deliberately revise tests that preserve legacy item-completion behavior. |
| APP-003 | CLI options, raw API JSON and malformed authentication-header errors can log credential data before existing redaction applies. | Apply one explicit redaction policy at each entry point; log safe metadata. |

## Which abstractions should change

| Current abstraction | Assessment | Direction |
| --- | --- | --- |
| Original SchedulerMain and injected service graph | Keep. Startup and leader-active phases carry real readiness semantics. | Make shutdown/partial-start ownership explicit within this graph. |
| Storage callbacks and seven store capabilities | Keep. They define atomicity and readable/writable access. | Keep input validation outside fail-stop writes; stage asynchronous outcomes at commit boundaries. |
| GoAgentDriver | Too many responsibilities in one 1,012-line service. | Extract package-private log reading and retirement interval/handshake logic first; keep the driver as lifecycle owner. Preserve watch, Stop, cleanup and retirement fencing. |
| SqliteDatabase | Transaction/fencing state is cohesive; schema and filesystem backup work crowd it. | Extract schema migration and backup helpers under the same locks/connection ownership. Keep uncertain-commit and publication handling explicit. |
| Legacy periodic TaskReconciler | The current Go backend discards its reconciliation calls while scans and timers still run. | Make watch reconciliation the explicit strategy and remove redundant legacy scheduling in Go mode. Preserve RPC validation and timeout/kill policy. |
| Writable log/durability modules | Apparently dormant in the shipped composition; historical readers remain required. | Separate the import compatibility surface, then remove or relocate uninstantiated writer/module code after checking packaging and extension contracts. |
| Amount / Unit | An overly broad numeric abstraction with correctness defects. | Characterize and repair value semantics, then use Duration and exact domain quantities internally while retaining configuration adapters. |
| StateMachine / task-state interpreter | Keep the decision/effect distinction and transition graphs. | Fix transition capture/builder ownership; remove task-state SideEffect's unused wrapper state while retaining explicit action order. |
| Updater strategies | Keep. Batch, queue and variable-batch behavior are distinct policies. | Replace recursive completed-batch advancement with a loop; derive/index history once per evaluation. |
| Stats globals/caches | Lifetime, collision behavior and dynamic-name cardinality are spread across registries. | Retain StatsProvider; use owned registration and coherent snapshots, with a deliberate collision/retirement policy. |
| ResourceBag, ranges, bidirectional expiry caches | Keep. Sparse vectors, interval semantics and inverse cleanup matter. | Use local accumulators/EnumMaps and exact durations inside them; avoid new generic frameworks. |
| Authorization metadata and Thrift/Jakarta adapters | Keep. They enforce scope, wire defaults and exception behavior. | Simplify redundant wrappers at the edge without replacing the authorization or serialization contract. |

The driver/storage extractions are in-place refactors. They do not introduce a second scheduler, new agent transport, storage cache outside transactions, or HA work.

## Where modern Java helps

Use **records for validated immutable data**: TierInfo, TierConfig, TaskGroupKey, named rate samples, process profiles, leader observations and coherent metric snapshots. Preserve defensive copies, constructor checks, compatibility getters and explicit wire serialization. Generated Thrift beans, mutable accumulators, Guice-intercepted services and byte-array credential holders should not be blindly converted.

Use **Duration, enum-specialized collections and exhaustive switches** where the domain fits. Duration removes unit truncation when adopted carefully. EnumMap makes resource/SLA aggregation straightforward. Arrow switches make status/action classification clearer. Make public state constants immutable. Keep monotonic timing separate from wall time and preserve injected test clocks.

Prefer **simple loops and standard APIs** over indirect machinery: plain local maps instead of aggregation-only LoadingCaches, direct minimum/sum calculations instead of intermediate lists/sets, one stored snapshot instead of repeated lookups, built-in collectors with their ordering contracts checked, and try-with-resources where ordinary ownership applies. Cache immutable codecs on hot serialization paths; one-time startup parsing is a lower-value target.

Use **explicit resource lifetime**, not more threads, to improve concurrency. Virtual threads already serve some suitable paths; they do not replace backpressure, commit ordering, scheduled timers or shutdown coordination. No preview API is necessary. This project has no Java 8 compatibility requirement.

## Verification and limitations

The parent checked the P1 request/storage/assignment/comparator paths against current callers and tests, read all three subagent reports, verified backend scan/shutdown paths, and ran the helper probe. The policy reviewer independently checked the parent's BatchWorker finding. Backend re-review narrowed performance statements: agent wakeups coalesce; the second offer scan is conditional; singular update lookup already point-reads while plural keyed queries scan. Daemon executor leaks mean post-stop activity, not necessarily blocked JVM exit. Stale memory indexes are partly masked by final query predicates; retained memberships/job keys are the concrete concern.

No speedup, deletion count, production incident, full Thermos parity, full IPv6 support, or HA readiness is claimed by this review. Remaining uncertainty includes workload frequency, measured performance, external Kerberos/ZooKeeper behavior, custom module consumers and cross-language race behavior after future edits. Each area report identifies the validation needed before its recommendations are considered implemented.
